# Архитектурные решения (DECISIONS.md)

## Решение 1: доменные методы вместо публичного `setStatus`

**Проблема.** `setStatus(TripStatus)` позволяет перевести заявку в любой статус в обход бизнес-правил: DRAFT → COMPLETED, REJECTED → APPROVED, отмена COMPLETED. Инварианты конечного автомата не защищены.

**Решение.** Поле `status` объявлено `private`, публичного сеттера нет. Переходы только через `submit`, `approve`, `reject`, `cancel`, `complete`. Каждый метод проверяет предусловие через `requireStatus(...)` и при нарушении бросает `IllegalStateException` до присваивания.

**Следствие.** Недопустимый переход извне невозможен. При ошибке объект не меняется.

## Решение 2: минимальная длина причины в одной константе

**Проблема.** Вариант 1 меняет порог длины причины с 10 на 20. Дублирование числа по классам ломает изменение на защите.

**Решение.** `BusinessTrip.MIN_REJECTION_REASON_LENGTH = 20` — единственное место с порогом. `reject(...)` читает только её.

**Следствие.** Изменение порога — одна строка в одном классе.
